# نتیجه بررسی نسخه گردش‌کار — 2026-11-07

## آزمون‌های اجراشده

- Backend: 149 تست روی PostgreSQL محلی در دیتابیس مستقل `test_mlkino_regression_20261107`، موفق. تست‌های اولیه روی SQLite نیز موفق بودند؛ آزمون PostgreSQL خطای قفل روی JOIN اختیاری را آشکار کرد و قفل‌ها به `of=('self',)` محدود شدند.
- Panel: 137 تست در 31 مجموعه، موفق؛ build انتشار و TypeScript موفق.
- Landing: 6 تست قرارداد و build Next.js موفق.
- زنجیره migrations سرور با تاریخچه متفاوت در دیتابیس موقت از صفر اجرا شد؛ `makemigrations --check` بدون تغییر بود. Migrationهای محلی به تاریخچه اعمال‌شده سرور نگاشت می‌شوند؛ fake migration استفاده نمی‌شود.
- مرورگر Chrome در Demo سرور: کاتالوگ و نقشه واقعی، ورود سوپرادمین، گزارش‌های دفاتر/کارشناسان/عملیات/مالی، همگام‌سازی نشست پنل و لندینگ، عرض موبایل 390px، بدون pageerror یا پاسخ 5xx.
- سناریوی واقعی Demo: حساب مالک → ثبت ملک → ارجاع جغرافیایی → ورود کارشناس مسئول → پذیرش و انتشار → علاقه‌مندی خریدار → چت مرتبط با ملک → شماره تماس پس از احراز نشست → قرارداد مرتبط.
- رقابت واقعی PostgreSQL در Demo: دو رزرو هم‌زمان برای ظرفیت یک نفر، یک پاسخ 201 و یک 400؛ ظرفیت حفظ شد.
- رقابت واقعی پرداخت در Demo: صورتحساب 100.00، دو پرداخت 80.00؛ فقط یک پرداخت نهایی شد، دیگری 400، مانده دقیق 20.00. دسترسی کاربر نامرتبط به سند مالی 404 بود.
- تست فرم‌ها خطای واقعی مسیر `users/expert/` را آشکار کرد؛ فراخوانی‌ها به API موجود `users/?group=expert` اصلاح شد، بدون ساخت API موازی.

## تصاویر و سرعت

- گزارش اندازه تصاویر اصلی در `static-image-optimization.json` و تصاویر اضافه در `additional-static-webp.json` موجود است. تصاویر اصلی حدود 92٪ سبک‌تر شدند؛ تصاویر اضافه حدود 90٪. فایل اصلی حذف نشده است.
- تصویر ملک: decode واقعی، محدودیت حجم/ابعاد، حذف EXIF/GPS، WebP در عرض‌های 320/768/1600؛ avatar، مدارک تصویری و پیوست تصویری چت/تیکت هم normalize و WebP می‌شوند. SVG فعال، فایل جعلی و تصویر خراب رد می‌شوند.
- بارگذاری Home پنل تنبل شد. کاتالوگ بدون فیلتر به‌جای خواندن همه JSONها از صفحه‌بندی دیتابیس و ایندکس ترکیبی استفاده می‌کند. فیلترهای پیچیده فعلاً روی داده‌های اسکوپ‌شده در برنامه ارزیابی می‌شوند؛ برای مقیاس بسیار بزرگ، انتقال کامل این قسمت به queryهای indexed مرحله بعدی است.
- Lighthouse پیش از انتشار روی نسخه عمومی: امتیاز performance برابر 36، LCP≈48.3s، TBT≈10.5s، CLS=0 در همان اجرای آزمایشگاهی. این یک اجرای lab از شبکه دستگاه است، نه آمار کاربران و نه INP. نتیجه بعد از انتشار جدا ثبت خواهد شد؛ کاهش حجم فایل به‌تنهایی ادعای رسیدن به بودجه سرعت نیست.

## محیط و محدودیت‌ها

Demo روی سرور دیتابیس PostgreSQL، کلید JWT، کاربر سیستم و media مستقل دارد و هیچ dump واقعی وارد نشده است. فقط روی loopback در دسترس است و از SSH tunnel استفاده می‌کند. پیامک، کدپستی و تطبیق هویت واقعی در Demo مسدود هستند. رمز مشترک 123456789 فقط برای حساب‌های مصنوعی Demo است.

نرخ قانونی عدد ثابت اختراع‌شده ندارد؛ مدیر باید نسخه معتبر نرخ و تاریخ آن را تنظیم کند. ثبت پرداخت، ثبت حسابداری است و انتقال وجه بانکی انجام نمی‌دهد. موجودی سرویس جیبیت در بررسی قبلی کافی نبود؛ تست موفق شبکه واقعی پیامک/تطبیق هویت، و تماس صوتی/تصویری دو دستگاه مستقل در این مجموعه ادعا نمی‌شود.

## بررسی تکمیلی پس از تست رابط

- دکمه علاقه‌مندی خود لندینگ با حساب واقعی Demo تست شد: تغییر وضعیت قلب، ذخیره سمت سرور و حفظ پس از reload؛ بارگذاری لیست شناسه‌ها مستقل از صفحه‌بندی کارت‌هاست. اطلاعات حساب‌ها در Provider مجزا می‌شوند.
- نقشه پس از نزدیک شدن به دید کاربر initialize می‌شود. تصویر hero در عرض‌های 640/1024/1600 و لوگو در 160px ساخته شد؛ لوگوی 113KB به حدود 6KB رسید. پیش‌بارگذاری گسترده لینک‌ها غیرفعال و اتصال API preconnect شد.
- فرم مالی در مرورگر Demo، نسخه نرخ دارای مالیات را انتخاب و کمیسیون را محاسبه کرد؛ مبلغ به صورتحساب منتقل، درآمد و مالیات جدا ثبت و سند از همان رابط قطعی شد. هیچ انتقال بانکی صورت نگرفت.
- صفحه‌بندی واقعی SQL برای فهرست‌های گردش‌کار و مالی، جستجو، وضعیت و تفکیک نقش مشتری در CRM تست شد؛ جمع مالی از کل اسناد فیلترشده محاسبه می‌شود.
- آزمون تغییر نقش: کارشناس پس از تبدیل به کاربر عادی، دسترسی به CRM، فایل حرفه‌ای، ارجاع و مدیریت بازدید را از دست می‌دهد؛ پروفایل حفظ و پس از بازگشت نقش قابل دسترسی است.
- آزمون جداسازی دفاتر: دفتر جدید با جذب کارشناس، به فایل و قرارداد دارای شناسه دفتر قبلی دسترسی نمی‌گیرد. قطع عضویت، دسترسی قدیمی و انتشار وابسته به همان دفتر را می‌بندد، بدون حذف اطلاعات.
- پذیرش فایل اجاره، مالک را به نقش موجر نیز متصل می‌کند و درخواست اجاره برای متقاضی نقش مستأجر ایجاد می‌کند.
- HTTP/2 و فشرده‌سازی CSS/JS/JSON روی سه دامنه با بررسی hash تنظیمات، backup و nginx -t فعال شدند؛ TLS و قواعد private media حفظ شدند.
