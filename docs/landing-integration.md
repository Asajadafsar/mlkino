# اتصال لندینگ اصلی به پنل

منبع کامل لندینگ در `landing/` همین مخزن قرار دارد. راهنمای تنظیم دامنه در `landing/docs/PANEL-INTEGRATION.md` است.

- لندینگ محلی: http://localhost:3001
- پنل محلی: http://localhost:3000
- API محلی: http://127.0.0.1:8000

کاربر از ثبت ملک، ثبت درخواست یا جستجوی لندینگ به مسیر واقعی پنل می‌رود. اگر نشست ندارد، Home مسیر و فیلترهای فعلی را در `next` به صفحه ورود منتقل می‌کند. ورود با رمز، ورود پیامکی، تکمیل ثبت‌نام و لینک‌های رفت‌وبرگشت صفحات احراز هویت مقصد را حفظ می‌کنند. مقدار next تنها مسیر داخلی پنل است؛ URL خارجی و مسیر ورود حلقه‌ای رد می‌شود.

لندینگ وضعیت ورود را از `GET /accounts/session/` با کوکی HttpOnly موجود روی API می‌خواند. پاسخ فقط شناسه، نام، تصویر و عنوان نقش دارد و قابل کش نیست. توکن، رمز یا نشست از طریق query یا localStorage بین دامنه‌ها منتقل نمی‌شود. با نشست معتبر پنل، فرم مقصد مستقیماً باز می‌شود. داده‌های عمومی نمونه لندینگ در این مرحله به API خصوصی پنل متصل نشده‌اند.

اعتبارسنجی: ۱۳۰ تست فرانت پنل، TypeScript و بیلد؛ بیلد و تست لینک‌های لندینگ؛ تست واقعی مرورگر با ورود حساب مستقل روی SQLite ایزوله. این تغییرات در مخزن کامل Asajadafsar/mlkino پوش و با انتشار 20261105-001-landing مستقر شده‌اند؛ گزارش در public-deployment-20261105.md است.

آخرین طراحی لندینگ از `b993227` دریافت و با اتصال پنل ادغام شد. سیاست اختلال استعلام و پیشخوان جدید در [registration-outages.md](registration-outages.md) توضیح داده شده است.


اصلاح نشست لندینگ: دکمه حساب برای مهمان مستقیماً `/login` را باز می‌کند؛ برای کاربر واردشده، نام و نقش واقعی و لینک پیشخوان نمایش داده می‌شود. وضعیت با بازگشت به صفحه یا فوکوس دوباره دریافت می‌شود. access منقضی با refresh موجود تمدید می‌شود. `NEXT_PUBLIC_API_URL` باید همان API پنل باشد؛ برای لوکال نام میزبان localhost/127.0.0.1 با مرورگر هماهنگ می‌شود. در Production، دامنه‌های دقیق https://mlkino.com و https://www.mlkino.com برای درخواست credentialed مجازند؛ دسترسی عمومی CORS فعال نشده است.

`registration_required` با `has_profile` فرق دارد: فقط پیش‌نویس کاربر عادی که هنوز رمز قابل استفاده و پروفایل تکمیل‌شده ندارد باید ثبت‌نام را ادامه دهد. حساب موجود با رمز معتبر یا نقش مدیریتی، صرفاً به علت خالی‌بودن نشانی یا کد ملی از پنل به ثبت‌نام منتقل نمی‌شود.

تست رگرسیون: ورود مهمان به لاگین، نمایش نام پس از ورود، تمدید access، خروج و حذف نام، نمایش حساب در موبایل و ورود حساب قدیمی فاقد نشانی به فرم ثبت فایل؛ روی دیتابیس ایزوله لوکال.
