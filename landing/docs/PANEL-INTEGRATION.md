# اتصال لندینگ به پنل ملکینو

این مخزن لندینگ اصلی است و در کنار مخزن پنل نگهداری می‌شود؛ کد ورود یا حساب کاربران در آن تکرار نمی‌شود.

## اجرای محلی

- لندینگ: در همین پوشه `npm ci` و سپس `npm run dev`؛ آدرس `http://localhost:3001`.
- پنل: در مخزن کناری `mlkino`، دستور `npm --prefix frontend start`؛ آدرس `http://localhost:3000`.
- بک‌اند پنل: در همان مخزن، `python3 manage.py runserver 127.0.0.1:8000`.

در توسعه، مقصد لینک‌های پنل به‌صورت پیش‌فرض `http://localhost:3000` است. از یک نام میزبان یکسان، مثلاً localhost، برای پنل و لندینگ استفاده کنید.

## تنظیم مقصد انتشار

`NEXT_PUBLIC_PANEL_URL=https://panel.mlkino.com` را هنگام **build** تنظیم کنید. نمونه عمومی در `.env.example` است؛ متغیرهای NEXT_PUBLIC در بیلد ثابت می‌شوند. تغییر دامنه پس از build نیازمند build مجدد است. این مقدار فقط origin است و نباید مسیر، query یا credential داشته باشد.

## مسیرها

| عملیات | مقصد پنل |
|---|---|
| ملکینوی من | `/dashboard`؛ در نبود نشست، ورود پنل |
| ثبت ملک | `/files/create` |
| درخواست ملک | `/requests/create` |
| چت و تماس | `/chats` |
| جستجوی هدر | `/files?search=...` |
| ورود و ثبت‌نام | `/login` و `/signup` |

مسیرهای قدیمی `/panel`، `/panel/*`، `/login`، `/signup`، `/register` و `/support` روی لندینگ با redirect موقت به پنل هدایت می‌شوند.

پنل باید نسخه حاوی `frontend/src/Core/AuthDestination.ts` را داشته باشد: مقصد محافظت‌شده در query با نام `next` نگهداری می‌شود، بین ورود/ثبت‌نام حفظ می‌شود و بعد از ورود با رمز، ورود پیامکی یا تکمیل ثبت‌نام باز می‌شود. مقصد خارجی یا مسیر حلقه ورود پذیرفته نمی‌شود.

هیچ توکن یا رمز عبوری بین دامنه‌ها در URL منتقل نمی‌شود. همه درخواست‌های احراز هویت در خود پنل و با کوکی‌های فعلی آن انجام می‌شوند؛ اتصال ناوبری نیازمند بازکردن CORS برای لندینگ نیست.

## محدوده این مرحله

اتصال حساب و دکمه‌های عملیات انجام شده است. آگهی‌ها، شمارنده‌ها و بخش‌هایی از فیلترهای عمومی مخزن همچنان داده نمونه دارند. فرم‌های نمونه بازدید/پیام ملک، ثبت واقعی بک‌اند نیستند. انتشار آگهی‌های عمومی باید در مرحله بعد از یک API عمومیِ دارای سیاست انتشار تأمین شود؛ API خصوصی پنل نباید به کاربر ناشناس باز شود.

## بررسی‌ها

- `npm test`: مسیرهای اصلی و کدگذاری متن جستجوی فارسی.
- `npm run build`: بیلد تولید با فونت محلی Vazirmatn، بدون دریافت فونت از گوگل.
- تست مرورگر: ثبت فایل از لندینگ ← ورود پنل ← رفت‌وبرگشت ثبت‌نام/ورود ← ورود واقعی حساب آزمایشی ← فرم ثبت فایل؛ ثبت درخواست در موبایل با نشست موجود.
- مخزن اولیه در lint دارای ۷ خطای قبلی در کارت افقی، انتخاب حالت نمایش، مودال بازدید و مرتب‌سازی است؛ فایل‌های اتصال این مرحله خطای lint ندارند.

نتیجه نهایی بررسی این مرحله: ۲ تست لینک لندینگ، ۱۲۹ تست فرانت پنل، TypeScript و بیلد هر دو پروژه و مسیر واقعی ورود دسکتاپ/موبایل موفق بودند. رندر فیلتر واکنش‌گرا نیز برای SSR پایدار شد. تغییرات فعلاً محلی‌اند و روی GitHub یا Production منتشر نشده‌اند.
